### [2026-07-30] FIX — plafond Vercel ~5 Mo cassait l'upload de photos reelles
**Fichiers :** `src/lib/cloudinary.ts`, `src/lib/cloudinary-client-upload.ts` (nouveau), `src/app/actions/admin.ts`, `src/components/admin/PhotosManager.tsx`, `src/components/admin/PelliculeEditor.tsx`

Test avec fichiers synthetiques de tailles croissantes : 68 octets et 4 Mo passent, 6.7 Mo et 9.4 Mo font planter le navigateur ("This page couldn't load", crash de connexion sans erreur applicative). Verification independante : le meme fichier de 9.4 Mo s'upload sans probleme en direct vers Cloudinary (script Node hors app) — la limite ne vient donc ni de Cloudinary ni de MAX_UPLOAD_BYTES (12 Mo cote app). Cause reelle : Vercel plafonne le corps de requete d'une Serverless Function a ~4-5 Mo, en amont de Next.js — aucun reglage next.config.ts existant ne peut lever cette limite plateforme (regle #7, a distinguer de la regle #2 sur proxy.ts). Ce bug affectait aussi bien le nouveau module Pellicules que le module Photos existant (meme mecanisme d'upload par Server Action + FormData).

**Correctif architectural** : upload signe directement navigateur -> Cloudinary. Nouvelle fonction `getUploadSignature()` (signe timestamp+folder avec la cle secrete, jamais exposee au client) et Server Action `requestUploadSignature()` (ne renvoie que la signature, quelques octets). Nouveau helper client `uploadFileToCloudinary()` dans `cloudinary-client-upload.ts` : demande la signature, poste le fichier directement a l'API Cloudinary depuis le navigateur (jamais via une fonction Vercel), recupere url/publicId/dimensions. `uploadPhotoAction` et `uploadPelliculePhoto` (upload par Buffer cote serveur) supprimees — remplacees par upload signe + reutilisation de `assignPhotoFromLibrary`/`assignPelliculePhotoFromLibrary` (deja concues pour rattacher une photo deja presente sur Cloudinary, sans re-upload). Simplifie au passage le code (une seule fonction d'insertion DB par module au lieu de deux quasi-identiques). Cap taille remonte a 25 Mo (verifie cote client desormais, plus de limite plateforme a contourner). Donnees de test nettoyees (pellicule + assets Cloudinary de diagnostic supprimes apres coup). Build + typecheck + lint verifies propres. A retester en production avec une vraie photo lourde.
